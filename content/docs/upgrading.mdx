---
title: Upgrading to v1.4
description: Migrate Blueprints from Engine User Settings v1.1 to the Engine User Settings Subsystem introduced in v1.4.
---

In v1.4.0 every node moved to **`EngineUserSettingsSubsystem`**. The C++ library `EngineUserSettingsBPLibrary` and the `EngineUserSettings` Blueprint function library asset were removed.

<Steps>
  <Step>
    ### Back up your project

    Commit or copy your project before updating the plugin.
  </Step>
  <Step>
    ### C++ library nodes are redirected automatically

    Nodes from the old C++ library (RHI, feature level, materials, INI…) are migrated by the `CoreRedirects` in `Config/DefaultEngineUserSettings.ini`. Open every Blueprint that uses them and **save it once**.
  </Step>
  <Step>
    ### Replace the Blueprint function library nodes

    Nodes from the old `EngineUserSettings` Blueprint function library asset (render settings) **can't be redirected**. Blueprints that used them show errors after the update: replace each node using the table below.
  </Step>
</Steps>

<Callout type="info">The new rendering nodes don't take a **Controller** pin any more: they set console variables directly, so they also work in menus and Editor Utility Widgets.</Callout>

## Behavior changes

- **Get Current RHI / Get Preferred RHI** return **Unknown / Default** instead of Vulkan when nothing is saved or the RHI isn't recognized.
- **Set Preferred Feature Level** returns a `bool`: it saves SM5 and returns `false` when the GPU can't run SM6.
- **Every value is clamped** to a safe range when it's set and when it's reapplied at startup, including values edited by hand in `GameUserSettings.ini`.
- **Saved values from v1.1 keep working**: the plugin still uses `[/Script/Engine.RendererSettings]` for console variables.

## Example project

The plugin now includes an example map, `Content/Example/Maps/Example`, with an **Options** settings menu built entirely with these nodes. Open it to see a complete graphics menu.
